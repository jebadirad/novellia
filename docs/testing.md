## Running checks

Run `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm test`, `npm run test:integration`, `npm run build`, and `npm run test:e2e`. Configure `.env.test` and migrate `novellia_test` first as documented in the README. Do not run the integration and browser suites against the same test database simultaneously: integration setup clears its data.

Unit geocoder tests stub network responses so the suite does not depend on a public service's uptime. Integration tests use real PostgreSQL and actual route handlers. Browser tests exercise the rendered application with isolated fixtures. Migration tests create and remove only a random schema in the guarded test database.

## Remaining release checks

Hosted CRUD, address resolution, direct-page loads, and persistence across redeployment have been smoke-tested; see [verification](verification.md). Long-idle cold starts and sustained public-service availability remain operational checks. Chromium automation and axe checks do not establish Safari/Firefox compatibility or replace a manual screen-reader review. These are explicit release checks, not claimed covered by the local suite.
